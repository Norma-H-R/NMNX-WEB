# 模块 4 · Client（EA 接入层）

> 文档版本：`0.1.0` · 最后更新：`2026-10-03`

## 状态

**未开始**。目前 `/api/v1/client` 是个空路由组。

## 职责

EA（MT4/MT5）接入的**传输与安全**：

- 统一入口 + 别名路由
- **签名校验**（HMAC-SHA256）
- **防重放**（nonce 去重 + 时间窗）
- **幂等**（重复请求返回缓存结果，而不是重复处理）
- **响应签名**（防本机伪造 `active`）
- 限流

**不负责**：授权业务规则 —— 那是**模块 3 License**。

## 对外接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/client/ea/verify` | **统一入口** |
| POST | `/api/v1/client/ea/{product_code}/verify` | **别名路由**，内部转发到同一个处理器 |

保留别名路由的原因：满足"每个 EA 有自己的 URL"这种直觉诉求，同时不产生第二套实现。
`product_code` 也可以放在请求体里；两个位置都给了就以路由里的为准。

请求体：

```json
{
  "app_id":       "…",
  "product_code": "nmnx-master",
  "edition":      "pro",
  "version":      "1.4.2",
  "license_key":  "…",
  "machine_id":   "…",
  "nonce":        "…",
  "timestamp":    1759489752,
  "sign":         "HMAC-SHA256(…) 的十六进制"
}
```

响应体：

```json
{
  "active":      true,
  "grace_until": "2026-10-10T00:00:00+00:00",
  "expires_at":  "2026-12-31T23:59:59+00:00",
  "server_time": "2026-10-03T08:30:00+00:00",
  "sign":        "服务端签名"
}
```

## 安全设计（每条都有明确对手）

| 措施 | 防的是 |
|---|---|
| 响应签名 | 本机改 hosts / 拦截返回伪造 `active: true` |
| `server_time` | 客户端把系统时钟调早，绕过到期判断 |
| nonce 去重 + ±5 分钟时间窗 | 重放抓到的合法请求 |
| 幂等（重复请求返缓存结果） | EA 重试 / 网络抖动导致的重复扣费或重复写审计 |
| 限流 | 拿泄漏的授权码暴力试探 |

## 调用时机：EA 初始化时请求（**已确认**）

```
EA 在 OnInit（每次运行 / 初始化）
  → 请求本接口，携带它的参数（产品、版本、机器 / 账号标识…）
  → 服务端拿参数查库（授权、产品、机器绑定…）
  → 返回激活码 / 激活信息
```

**是"初始化时调用"，不是"实时心跳"。** 这一点很重要：它意味着

- 调用频率极低，**主线程阻塞问题基本不存在**
- 不需要频繁打 DB，Redis 缓存是锦上添花而非必需
- 但也带来一个必须定死的行为：**初始化时拿不到授权怎么办**（见下节）

### 待定：是否额外加"周期性复检"

只在 `OnInit` 调有一个后果：**EA 长时间挂在图表上时，感知不到授权到期或被吊销**
（除非用户重挂 EA / 换周期 / 重启终端）。

| 方案 | 优点 | 缺点 |
|---|---|---|
| 只在 `OnInit` 调 | 最简单、最省 | 长期运行的 EA 不会自动失效 |
| `OnInit` + `OnTimer` 复检（比如每 60~300s） | 能感知吊销与到期 | 需要频率控制；`WebRequest` **会阻塞**主线程，所以绝不能每 tick 调 |

**待定，但两个方向都要能支持**——所以接口本身必须**幂等**，重复调用不能产生副作用。

### 初始化失败时的行为（必须定）

这是这个模块最要紧的一条：EA 初始化拿不到授权，是要"**拒绝运行**"还是"**宽限期内继续跑**"？

交易系统绝不能因为我们服务器抖动就断单，所以方向是后者：
**返回的授权信息里必须带 `grace_until`，EA 侧在宽限期内照常运行。**
具体判定规则在模块 3 License，本模块只负责把这个字段原样带回去。

## 现实约束（MQL 侧）

EA 是 MQL 写的，`WebRequest`：

- 只支持 GET / POST
- 有频率限制，且**会阻塞**主线程（所以调用次数要少 —— 初始化时调一次正好合适）
- 只认 JSON
- 必须 HTTPS
- 对超时极其敏感

所以接口必须在 **1~2 秒内**返回，且**不能**在关键路径上做慢查询或同步写审计日志。

## 关于"加密"：一期只留接口，不实现算法（**已确认**）

D3 定的是"不走明文"，但**一期不实现任何加密算法**：

- 请求 / 响应结构里**预留加密相关的字段**（`key_id`、`enc`、算法标识等）
- 代码里留出 `Encryptor` 抽象与注入点
- **算法怎么定、怎么协商，后期再实现**

所以这个模块一期的实现难度**不在加密上**，而在"**请求字段与响应字段的形状**"上 ——
字段一旦发出去，已经装在别人机器上的 EA 就改不动了。**字段设计要一次到位。**

## 数据表

- nonce 与幂等键**放 Redis**，不进 DB（量大、有 TTL，天然适合）
- `app_id` → secret 的映射：**待定**（表 or 配置）

## 配置与环境变量

| 配置 | 建议值 | 说明 |
|---|---|---|
| 时间窗 | ±300 秒 | 与 `timestamp` 比对 |
| nonce TTL | 600 秒 | 略大于时间窗，够覆盖窗口即可 |
| 幂等结果 TTL | 300 秒 | EA 重试窗口 |
| 限流 | 待定 | 每条授权码 / 每个 IP |
